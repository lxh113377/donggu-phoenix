# Skill 治理 · 长效维护规范（要求 5 + 6 验证口径 + 要求 7 收口）

> 适用范围：`D:\global_skills` 全部受管技能 + 九端镜像。本规范与 A-skill-manager 铁律并存，冲突处以本规范的「巡检增补条款」为新增义务、以 A-skill-manager 既有铁律为执行形态。

## 1. 季度巡检机制（要求 5 的落地件）

### 1.1 执行件
- **扫描器**：`tools/skill_quota_scan.py`（本仓，stdlib-only，退出码 0/1/2 与 workflow_gate 口径一致）。已实测跑通（基线 `_skill_audit\scan_baseline_test.json`：8 试点件、attention 4、上游读数全活）。
- **判红五项**：① 主文件 >12288B（soft cap，棘轮制：只降不升）② `.upstream` 声明的上游 last-commit ≥6 个月（"months/years/never"）③ 上游不可达 ④ `*.pyc` **孤儿**（同名 .py 源已不存在者；在库活跃 .pyc 属合法构建产物不判红——轮2 实测修正：门禁运行时重建活跃缓存会致假阳，判据只认孤儿） ⑤ retired_skills 名册命中仍在盘/仍被引用（三路存活核验，A-skill-manager 铁律 6）。
- **新增字段义务**：每个 SKILL.md frontmatter 必含 `last_updated`（Phase 0.3 批量补齐后，新建/改动即更新；巡检报告按">12 个月无 last_updated 变动"排黄）。
- **上游声明义务**：包装类 skill（本质封装某开源 CLI/库/规范）必建 `.upstream` sidecar，每行 `owner/repo`（shields 徽章只认仓库根；子目录技能如 anthropics docx 统一写仓库根 `anthropics/skills`）。

### 1.2 排期与闭环
- **每季度首月 1 日 09:00（Asia/Shanghai）**自动扫描（会话排程已挂，crontab 表达式 `0 9 1 1,4,7,10 *`）。
- 产物：`_skill_audit\scan_<YYYYQn>.json` + 人类摘要落本目录 `季度巡检-<YYYYQn>.md`。
- 判红项 → 自动生成待办写入各仓 `memory/05-next-steps.md`（handoff flow 管线），责任人=当轮值守端。
- 升级动作触发条件：上游 major 版本跃迁 **或** 连续两季同项排红 → 走 A-skill-manager「主动增删改」管线（intent-crud），不得静默改。
- 退役触发条件：同族职能重叠且新件路由实测零误命中 → 双硬前提（_trash 备份 + git 可回滚）满足即自动批准（2026-09-24 立规），受保护件除外。

### 1.3 上游检索的卫生规则（B 代理教训固化）
- 候选仓库**必须逐一经 API/页面实测存在**才可进评估表：本轮实测证伪 8 个「看似真名」（garrytan/claude-code-config→garrytan/gstack、getzep/zep-oss 已停维、tobi/lazy-agents 404 等）。**二手清单（文章/记忆/模型口述）不得直接进决策面**。
- 许可雷区前置核对：AGPL（basic-memory 类）禁入 junction 九端分发面；NOASSERTION/无 SPDX 检出（anthropics/skills 根、vercel-labs/agent-skills）→ 仅允许私有镜像+注明 source-available 边界；替换前先读 LICENSE 原文。

## 2. 质量提升 ≥30% 的验证口径（要求 6）

### 2.1 主指标（替换类动作）
**Q = 任务成功率 × 首次通过率 × 效率系数**，在固定 10 任务基准套件上测：
- 套件：浏览器 10 任务（导航/填表/登录复用/截图/批量页面/a11y/录像/网络桩/拖拽/上传）+ 文档 5 任务（docx 报告/xlsx 透视/pptx 生成/pdf 抽取/模板填充）+ 路由 5 冲突语句集。
- 基线 = Phase 0 前 HEAD 快照实测（agent-browser 已有：命令覆盖 71.1%、厚版 30KB；A/B 读数 `_skill_audit\ab_agent_browser.json`）。
- 提升幅度 = (Q_new − Q_base)/Q_base ×100%，**分件判定 ≥30%**；A/B 试点预测 +35%~45%，正式判定以套件实跑为准。
- 辅助指标：命令面覆盖率、主文件字节、路由误命中数、lessons 缺陷缓解覆盖率。

### 2.1b 双口径声明（r6 跑前预登记，防移动门柱）

主判定采两口径，任一达标即满足要求 6 之「质量提升 ≥30%」，跑前先声明后读数：
- **口径 A（套件提升）**：十任务双臂 Q=成功率×首过率×效率，直连二进制公平形态（r6 起 npx 冷解析慢因已除），T03 动态取 ref 为有效任务；判定线 lift≥30%。
- **口径 B（矩阵合成提升）**：五维加权合成中「运行效率×0.20+功能完整性×0.30」两维的相对提升加权合成（效率=体量税+漂移免疫，功能=命令面覆盖率），以 02 矩阵 current→best 实测差值合成。

### 2.2 兼容性护栏（一票否决）
- 业务回归：本仓 `tools/verify_site.py`（158 项）全绿 + GitHub Pages/Cloudflare 双链部署实测 200。
- 既有约定零改动：memory/ 台账九文件结构、AGENTS.md 绑定表、九端 junction 启动协议、七步闭环衔接、`_my-skills` 受保护名册。
- 行为不回归：替换后跑「原有业务 5 场景」清单（登录复用/扫码验证/AR 页面 QA/批量截图/文档交付），任一失败即触发回滚。

### 2.3 判定与留痕
每阶段收口出「验证 Gate 记录」：扫描器 rc + 套件分数对比表 + git SHA + _trash 路径，四要素缺一不算闭环（verification-before-completion 口径）。

## 3. 日常维护规则（防复发）

1. **薄壳原则**：封装开源 CLI 的 skill，主文件≤12KB；命令/参数细节以「上游 `skills get`/`--help` 现读」为主源，本地只写工作流约定、私有踩坑、缺陷缓解（agent-browser v2 的 `skills get core` 委托模式为范式）。
2. **缺陷入文即闭环**：lessons 记录的上游缺陷，对应 skill 必须同轮或下轮补「缓解章节」，覆盖率进巡检报表。
3. **版本锚点**：包装类 frontmatter 加 `upstream-version: x.y.z`，巡检比对上游 latest_release，落后即排黄。
4. **改动走权威源**：只改 `D:\global_skills\`，改后 -Fix 同步镜像、复核 missing=0/mismatch=0（A-skill-manager 铁律 8，本规范重申）。
5. **派生件权威链不动**：unified-skills-index → build_indexes --apply → skill_content/*.json，禁直改、禁 scan 全量重生（铁律 4）。
6. **拆卷不拆行为**：体量治理一律 bigfile-split 管线（指针壳+语义卷，byte_identical 核验），12KB soft + 棘轮。
7. **frontmatter 键扩展成对制**：新增顶层键必先过焚诀 C28 `ALLOWED_KEYS`（2026-09-24 冻结集）——跨仓新字段按轮41 规程「白名单放行 + 真判据」成对提交后才可用；未登记前版本锚点走正文行 + `.upstream` sidecar（轮2 实测：upstream-version 直写 frontmatter 即判 A3 违规）。
8. **删除零硬删**：一律 cp/mv → `_trash\<标签>_<ts>\` 且整体出树（铁律 3），回收站通道（handoff recycle）兜底。
9. **NO-EQUIVALENT 也是结论**：检索无等价物时如实记录（本轮 A 系列 5 件），禁为"完成替换指标"硬凑迁移——强迁治理件=质量倒退。
