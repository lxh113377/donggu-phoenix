# 体验深化与轻量化 AR 展示方案

> 命题：如何运用轻量化 AR 技术，把静态文化资源转化为具体可感的沉浸式体验产品，延长游客停留时间。
> 对应交付物：本站 AR 展陈馆（三段 13 章 152 秒）+ 文创 + 二维码动线。
> 本文件回答「为什么这么做」与「怎么被验证」，实现细节见 `docs/交付说明.md` §6.5。

---

## 一、问题拆成三件事

| 问题 | 具体表现 | 本站的解法 |
|---|---|---|
| 文化资源是**静态**的 | 一尊木雕神像、一处旧居，看不懂工序、不知道发生过什么 | 把「看不见的过程」做成动画：选木→开光五道工序；把「看不见的场景」复原成画面：会师、合围、冲锋 |
| AR 往往**很重** | 3D 模型包、WebGL 追踪库、下载几百 KB 到几 MB，现场网速一差就打不开 | 全部 Canvas 2D 参数化绘制；零模型文件、零第三方库、零外部请求；摄像头只作底片 |
| 停留时间**短** | 扫完看一眼就走，展板前的平均停留常在一分钟内 | 分段叙事（13 章）+ 集章 + 进度与计时可见 + 卡片先报时长 |

## 二、轻量化的三条硬线（可验证，不靠形容词）

1. **零 3D 模型文件**：站点内不存在 `.glb/.gltf/.obj/.fbx`，三段共 44KB 渲染代码。
2. **零第三方库**：不引 three.js / AR.js / 8thWall / OpenCV.js；页面只有 4 个本地脚本。
3. **零外部请求**：`src|href` 中的 http(s) 外链必须为 0（文献链接只作文本）。

> 这三条由 `tools/verify_site.py` 在每次交付前自动校验，FAIL 即阻断发布。

## 三、沉浸感从哪来（而不是靠模型精不精）

| 手法 | 具体做法 |
|---|---|
| 时间结构 | 每段有明确起承转合：造像从一段木料走到「开光」落印；红色按 1929→1931 四年推进 |
| 视觉锚点 | 造像始终以同一尊轮廓贯穿五章，观众看到的是同一尊像被「一步步做出来」，而不是五张无关的图 |
| 现实叠合 | 摄像头取景铺底，动画以半透明图层压在其上；对准后取景框收拢并自动开演，制造「它就在你面前」的观感 |
| 双语 | 每章中英双语并排，外来观众也能读；对应「双语解码东固」的项目定位 |
| 可操作 | 上一段/下一段/重播/进度条/键盘快捷键；不强迫线性看完 |

## 四、停留时长怎么被拉长的（设计机制，非实测结论）

| 机制 | 作用 |
|---|---|
| 分段 + 时长预告 | 卡片上直接写「时长 72s · 落『造像章』」，降低「不知道要看多久」的退出 |
| 集章 | 每段落一枚朱印，三枚集齐提示「已解锁完整动线」；完成感驱动看完第二、第三段 |
| 停留计时 | 页脚实时显示「本页 AR 已停留 mm:ss」，把「停留」变成可见的自我进度 |
| 本地持久化 | `localStorage` 记住已集章，下次扫码接着看，不重复也不丢失 |
| 内容钩子 | 每章一句具体史实（如「前头捉了张辉瓒」），给二次传播留话头 |

> 三段连播 152 秒；加上读解说与集章，**设计目标**停留约 4–6 分钟。这是设计估算，不是现场实测数据；
> 若要作为项目指标上报，需在展板现场做 A/B（有无 AR）计时统计。

## 五、降级与包容性（现场不出事故的前提）

- 摄像头不可用 / 权限拒绝 / 非 https → 「展柜模式」，同一套动画照常播，toast 说明原因；
- `prefers-reduced-motion` → 不自动播放，直接给信息最完整的关键帧，可手动逐章翻；
- 无 canvas（极旧设备）→ 页面其余部分不受影响；
- 键盘可用：Esc 关闭、← → 切章、空格暂停。

## 六、已知边界（诚实清单）

| 边界 | 说明 | 下一步 |
|---|---|---|
| 不是真 AR 追踪 | 摄像头只作背景底片，识别是「暖色像素占比」判定，不做平面/图像跟踪 | 若确需贴面叠加，引 OpenCV.js 模板匹配（约 +600KB），需权衡首屏 |
| 三维感有限 | 造像是参数化矢量剪影，不是高模 | 若能拿到造像多角度实拍，可换成交互式序列帧 |
| 未做真机实测 | iPhone Safari / 微信内置的曝光与对焦差异未验证 | 线下设备实测 + 阈值调参 |
| 停留时长为设计估算 | 见第四节说明 | 现场 A/B 计时 |

## 七、一页速览

```
扫码 → 落地页（凤凰粒子 + 三张场景卡）
     → 点「开演」→ 全屏层：摄像头底片 + 动画叠加 + 解说 + 进度
     → 看完落章 → 三章集齐 → 去文创区看落地载体 → 页脚二维码二次传播
```

停留不是靠一段长视频撑出来的，是靠「一段一段有终点、有奖励、可随时停」的结构撑出来的。
