## 3. 逐项差距说明（每条带实测数字与证据位置）

### 3.1 功能模块覆盖范围
**本项目对应模块定位**：`ar-scenes.js`(44.3KB) = 展陈内容渲染器（对 OSD/UV 的 viewer 层）｜`ar.js`(19.8KB) = 播放控制层（对 aframe scene+system 混合体）｜`phoenix.js`(11.3KB) = 粒子引擎（对 particles.js）｜`main.js`(12.8KB) = 页面装配｜`culture.js`/`ar-data.js` = 内容源（对 Mirador 数据层）。

**明确缺失（全部实测）**
1. **音频/旁白/字幕通道 = 0**：站点内音视频、vtt、srt 文件实测 **0 个**；`<track>` = 0；`speechSynthesis` = 0。152 秒叙事完全依赖视觉阅读。对照 UV `__tests__/av_tests.js` + `uv-youtube-config.json`（影音是一等公民）。影响：视障用户不可达；**乡村展陈现场恰是嘈杂环境**，纯文字阅读效率最低。
2. **语种切换机制 = 0**：`hreflang` = 0，双语靠 `ar-body-en` class + 单个 `lang="en"` 元素（index.html 实测）——是"中英同时铺"而非"可切换"。对照 Mirador `src/locales` **24 项** + `demo/rtl.html`。
3. **搜索/标注/多窗口 = 0**：对照 Mirador `demo/content-search.html`、`svg-annotations.html`。属层级差（本项目无海量资产需检索），**不计入必改项**。
4. **图片响应式 = 0**：`srcset` = 0，`loading="lazy"` 仅 1 处；最大单图 `merch-sketch.webp` **97,426B** 一次性进首屏。

**本项目独有优势（9 个 peer 全部没有）**

- **展柜模式**：无摄像头/拒权限/非 https 时同一套动画照常完整播放（实测降级链生效）；
- 集章 + 停留计时**全本地**：`donggu-ar-v1` 实测可持久化（`{stamps,dwell,visits,at}`），零上传零账号。

### 3.2 技术架构设计
**实测分层现状**：4 个脚本靠全局变量串联（`window.CULTURE / AR_DATA / Phoenix / AR_SCENES / __ar / __site / __phoenix`），无模块系统、无依赖声明，**加载顺序即隐式契约**（index.html 底部 6 个 `<script>` 无 defer/async）。

**对照 `aframevr/aframe`（一手：`src/core/system.js` 全文 4,703B + `src/core/component.js` 25,830B 已读）**
| aframe 机制（原文证据） | 本项目现状 | 判定 |
|---|---|---|
| System = 全局作用域服务，注释原话 "help abstract logic away from components such that components only have to worry about data" | 全局逻辑（`resize`/`raf`/`fps 统计`）与实体逻辑（`scene.draw`）写在同一个 `ar.js` 闭包里 | 职责混排 |
| `System.prototype = { init, update, tick, tock, play, pause }`，**默认全部 no-op**，消费方只覆盖所需 | `CraftScene/RedScene/PhoenixScene` 各自实现 `seek/draw`，但控制器 `state.playing` 逻辑在 `ar.js` 内硬编码三份共用 | 半达成 |
| `registerSystem`：**重复注册即 throw**，报错文案直接给出排查方向（"Check that you are not loading two versions of the same system…"） | `AR_SCENES.create()` 是 `if/else` 工厂，未知 id **静默返回 null**（`ar.js` 的 `loadScene` 再 `if (!data) return`） | 缺可诊断性 |
| `events` 映射表随 `pause/remove` **自动解绑** | `bind()` 注册 `visibilitychange`/`hashchange`/`resize`/`click`/`keydown` 后**从不解绑**；`close()` 只解 `trapTab` | 泄漏面（单页应用影响小，但属规范缺位） |
| 高频事件 `throttleLeadingAndTrailing(…, 200)`——注释明确"burst 后末次必发，保证消费者读到正确终态" | `paintHud()` 在 `frame()` 内**每帧无条件写 DOM**（bar 宽 + time + dwell + play 文案）；实测 fps 224 ⇒ **每秒 ~224 次布局写入** | 可消除开销 |

**对照 `VincentGarreau/particles.js`（一手 43,009B 已读）**：`number.density.value_area = 800` 使粒子数随画布面积自适应；rAF polyfill 带 `setTimeout(1000/60)` 兜底。本项目仅 `innerWidth < 900` 一档断点（2600/1500）——**4K 与 1080p 同为 2600**，密度既无余量反馈也无上限保护。

**反向结论（本项目更强，须保留）**：`phoenix.js` 用 `p.k*(dt/16.7)` 与 `Math.pow(p.damp, dt/16.7)` 做 **dt 归一化**，particles.js 无帧间隔归一化（120Hz 屏或掉帧时速度漂移）。**此点不是差距，是优势。**

### 6.2 关键功能复现（本轮实跑，非设想）
1. **浏览器度量通路从零打通**：`agent-browser 0.31.1`（`D:\npm-global`，引擎 = 本机 Edge）跑通 `open → wait --load networkidle → eval → vitals → set offline → press Tab → screenshot` 全链，产出本项目 FCP/LCP/CLS/TTFB 与 fps/帧距/堆/DOM 一手数据。踩掉并解决 **4 个真坑**：
   - **`.cmd` 垫片被 cmd.exe 二次解析**：`&&`、`!!`、`|` 被吞 ⇒ 必须走 `agent-browser.ps1`；
   - **PowerShell→native.exe 参数重引用吞掉 JS 里的双引号**：`meta[property="og:image"]` 变成非法选择器 `meta[property=og:image]` ⇒ 规则：**传进 eval 的 JS 严禁双引号**，需要引号用 `String.fromCharCode(34)`，长表达式落临时文件再 `ReadAllText` 传参；
   - **`eval` 返回 JSON 会被再包一层字符串**：直接 `JSON.parse` 得字符串而非对象 ⇒ 让 JS **返回标量**或自行二次 parse；
   - **`spawnSync` 捕获子进程 stdout 在沙箱下返回空**（EPERM 边界）⇒ 改由 PowerShell 管道 `Out-String` 承接。
2. **离线行为复现（避免一次错判）**：`set offline on` 后重开线上站**居然仍能打开** —— 若就此收工会得出"PWA 已具备"的**错判**。继续追判据：`sw.controller = null`、`getRegistrations() = []`、`/sw.js = 404`、`/manifest.webmanifest = 404`、响应头 `cache-control: max-age=600` ⇒ 真相是**磁盘缓存在兜底，不是 Service Worker**。→ 定为 I-2（高优）。
3. **焦点陷阱复测（推翻自己的假设）**：Tab 遍历 16 次得 **IN 16/16、泄漏 0** ⇒ 推翻"陷阱坏"的初判，确认 commit `9fbe83a` 修复有效。§3.3 已据此**改正结论**，不保留误判。
