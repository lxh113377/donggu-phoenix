## 四、凤凰动画技术实现

**不是视频，是实时粒子系统**（约 2600 粒子，桌面端稳定 200+ fps，手机端 ≤1500 粒子）。

```
assets/img/phoenix-particle.svg   纯剪影（供像素采样）
        ↓ 采样为 460×460 位图
assets/js/phoenix.js             坐标 → 粒子目标点，按位置着色
        ↓
状态机：assemble（组装）→ idle（呼吸）→ burst（碎裂）→ flight（飞舞）→ settle（归位）
```

**配色映射（取自凤凰装实色）**：
- 翼根 `#7A1420` 深红 → 翼中 `#D94F2B` 桃红 → 翼尖 `#E8B761` 金
- 尾羽 `#E8B761` 金 → `#1E3A5F` 深蓝
- 身体 `#E8325A` 朱红高光

**三级降级链**（保证任何设备都不白屏）：
1. 真机摄像头 → 取景框内暖色像素占比 >16% 判定"已对准图腾" → 触发
2. 摄像头不可用 / 权限拒绝 / 非 https → 自动切「点击召唤」
3. `prefers-reduced-motion` 或无 canvas → 静态光点图腾（一次性绘制）

### 6.5.2 「轻量化」落在哪几条硬约束上

| 约束 | 做法 | 证据 |
|---|---|---|
| 零 3D 模型文件 | 三段全部 Canvas 2D 实时绘制（`ar-scenes.js`），造像、红旗、山谷、凤凰均为参数化矢量 | `verify_site.py` 检查站点无 `.glb/.gltf/.obj/.fbx` |
| 零第三方库 | 无 three.js / AR.js / 8thWall，无 npm 依赖 | 页面只加载本地脚本 |
| 零外部请求 | 脚本、图片来源本地；文献链接仅作文本展示，不发起请求 | `verify_site.py` 校验 `src|href` 中 http 外链必须为 0 |
| 不拖慢首屏 | AR 独立成文件，点击「开演」才进入全屏层 | 首屏仍是凤凰粒子主视觉 |
| 摄像头可选 | 摄像头只作背景底片；不可用/被拒/非 https 自动切「展柜模式」，同一套动画照常播 | 实测拒绝授权后 `mode=gallery` 且动画继续 |

### 6.5.3 现实叠加怎么实现（无 CV 库的取景判定）

```
getUserMedia(environment) → <video> 铺底（opacity .42）
        ↓
72×72 探针画布，取中心 60% 区域，统计暖色（红/金）像素占比
        ↓
>16% → 判定「已对准」→ 加 .locked（取景框收拢）→ 900ms 后自动开演
≤16% 持续 4s → 提示「对准后自动叠加，也可直接开演」，不阻断
摄像头失败 → 展柜模式（toast 说明原因），不降级内容
```

### 6.5.4 停留时长设计（对应「延长游客停留」命题）

- **分段可跳可重播**：上一段 / 下一段按章节跳转，进度条 + 时间码可见
- **集章机制**：每段结束落一枚朱印（`localStorage` 持久化），三枚集齐提示解锁完整动线
- **停留计时**：播放时累计，页脚实时显示「本页 AR 已停留 mm:ss」
- **卡片预告**：落地页每张卡先列章节名与时长，降低「不知道要看多久」的退出率
- **无障碍**：`prefers-reduced-motion` 下不自动播放，直接给一帧信息最完整的关键帧（造像 50s / 红色 3s / 凤凰 16s），可手动逐章翻看

- 粒子动画在中低端安卓机上会降到 30fps 左右（已按屏宽自动降至 1500 粒子）。
