## 四、凤凰动画技术实现

**不是视频，是实时粒子系统**（约 2600 粒子，桌面端稳定 200+ fps，手机端 ≤1500 粒子）。

```
assets/img/phoenix-particle.svg   纯剪影（供像素采样）
        ↓ 采样为 460×460 位图
assets/js/phoenix.js             坐标 → 粒子目标点，按位置着色
        ↓
状态机：assemble（组装）→ idle（呼吸）→ burst（碎裂）→ flight（飞舞）→ settle（归位）
```

**配色映射（取自凤凰装实色）**：
- 翼根 `#7A1420` 深红 → 翼中 `#D94F2B` 桃红 → 翼尖 `#E8B761` 金
- 尾羽 `#E8B761` 金 → `#1E3A5F` 深蓝
- 身体 `#E8325A` 朱红高光

**三级降级链**（保证任何设备都不白屏）：
1. 真机摄像头 → 取景框内暖色像素占比 >16% 判定"已对准图腾" → 触发
2. 摄像头不可用 / 权限拒绝 / 非 https → 自动切「点击召唤」
3. `prefers-reduced-motion` 或无 canvas → 静态光点图腾（一次性绘制）

### 6.5.1a 一木成像：可拖动的雕刻过程（本版新增）

场景一原来按五章各画一帧，读者看到的是「五个结果」。本版把它改成**一段连续的雕刻**：落地页新增「一木成像」雕刻台，一根进度轴从一段樟木推到开光，观众可以自己在画面上按住左右拖、拖滑杆、或聚焦后按方向键推刀。

| 项 | 做法 |
|---|---|
| 单一进度轴 | `p ∈ [0,1]`；像身轮廓由参数化剖面 `halfWidth(u, 开坯量)` 定义，开坯是沿像身自上而下推进的**波前**（带跳刀抖动），所以木料与神像是同一根木头被逐步让出来，不是两个图形交叉淡入淡出 |
| 六工序刻度 | 选木 / 定像 / 开坯 / 修光 / 彩绘贴金 / 开光；点击任一工序直接跳到该段起点，解说与高亮同步 |
| 器具随工序 | 斧（柄 + 斧眼 + 外扩刃口）、凿与木槌、含漆毛笔、持箔竹镊，均在对应进度窗口内出现并随时间摆动 |
| 材质细节 | 木料年轮盘按**当前料口实际半宽**绘制，波前推过头部即随料口消失；修光阶段刀痕渐次收干净；贴金自上而下推进并带箔屑飞散；开光起舟形背光、头光、仪轨珠、香烟与朱印 |
| 背景板 | 整块木纹 + 木节涡纹 + 三层墨色山峦剪影 + 岭脊亮边 + 暗角，取自「东固传统造像」宣传物料的木作底与山景构图；代码绘制，无位图资源 | 与海报同源观感，但不引入任何图片请求 |
| 与 AR 同源 | `ar-scenes.js` 的场景一改调同一引擎，AR 五章通过 `progress(章序, 章内进度)` 映射到同一根轴上；两处画面严格一致，不再各画一套几何 |
| 降级 | `prefers-reduced-motion` 下不自动播放，直接停在成品像并提示可用滑杆回看；画布 `role="slider"` + 方向键可操作；滚出视口即停表省电 |
| 口径 | AR 仍按论文的五道工序分章（选木 / 定像 / 开坯 / 修光·彩绘·贴金 / 开光）；雕刻台把第四章拆成修光与彩绘贴金两格刻度，是**展示粒度**的差异，不是工序名目的改动 |

素材口径补充：樟木用料与「开面」分寸（威而不怖、亲而不俗）取自《井冈山报》2026-08-10《樟木深处听刀音——记国家级非遗项目东固传统造像代表性传承人刘节明》；「明初 · 南京工部匠籍雕銮匠、廿余代、六百余年」同据该文与吉安市人民政府专题页。画面为团队原创参数化矢量，非实拍。

### 6.5.3 现实叠加怎么实现（无 CV 库的取景判定）

```
getUserMedia(environment) → <video> 铺底（opacity .42）
        ↓
72×72 探针画布，取中心 60% 区域，统计暖色（红/金）像素占比
        ↓
>16% → 判定「已对准」→ 加 .locked（取景框收拢）→ 900ms 后自动开演
≤16% 持续 4s → 提示「对准后自动叠加，也可直接开演」，不阻断
摄像头失败 → 展柜模式（toast 说明原因），不降级内容
```

### 6.5.4 停留时长设计（对应「延长游客停留」命题）

- **分段可跳可重播**：上一段 / 下一段按章节跳转，进度条 + 时间码可见
- **集章机制**：每段结束落一枚朱印（`localStorage` 持久化），三枚集齐提示解锁完整动线
- **停留计时**：播放时累计，页脚实时显示「本页 AR 已停留 mm:ss」
- **卡片预告**：落地页每张卡先列章节名与时长，降低「不知道要看多久」的退出率
- **无障碍**：`prefers-reduced-motion` 下不自动播放，直接给一帧信息最完整的关键帧（造像 50s / 红色 3s / 凤凰 16s），可手动逐章翻看

## 六·六、设计系统 v2（轮5 · 2026-10-20，对标 Awwwards / Webby / FWA 的品质线）

> 这一轮不加功能，只把「能用」抬到「看得出用心」。八项自检口径 = 排版 / 留白 / 视觉层级 / 色彩 / 动效 / 微交互 / 响应式 / 原创性。

### 6.6.1 排版：从「系统默认宋体」到有笔锋的展示字体

| 项 | 改前 | 改后 |
|---|---|---|
| 标题字族 | 系统楷体（Windows 回落成 KaiTi，Mac 是 STKaiti，安卓没有 → 三端三样） | **ZCOOL 小薇**（自托管子集，1125 字 / 238KB），三端一致 |
| 拉丁小字 | PingFang / 微软雅黑 | **Cinzel**（罗马碑体大写，14KB），英文 kicker 有金石气 |
| 字阶 | 各处随手 rem，共 23 个离散字号 | **11 档令牌** `--fs-*`，下限 11px，最大 `clamp(3rem,7.6vw,6.5rem)` |
| 行高/字距 | 混用 1.8 / 1.85 / 40px 硬编码 | 正文 1.8–2.0，标题按中文字距单独给（.06–.16em） |

字体为什么自托管而不是引 Google Fonts：项目硬约束是**零外部请求**（现场网络不可控）。
把 238KB 记在本地预算里，比让首屏去等一个可能被墙的 CDN 更诚实。授权为 OFL 1.1，
版权行随产物发布在 `site/assets/fonts/LICENSE.txt`。

### 6.6.2 留白：统一节奏，而不是每段各写一个 padding

- 段间距统一 `--sec-y: clamp(88px,11vw,148px)`；容器统一 `--maxw:1180px` + `--gut` 双侧留白。
- `.sec-head` 改为三栏（编号 / 标题 / 导语），导语右对齐独立成栏 —— 标题不再和正文挤在同一行宽里。
- 段落之间加**手绘墨线分隔**（SVG path，滚动时用 dashoffset 画出来），比一条 1px 直线更像「手工装帧」。

### 6.6.3 视觉层级：三处拆掉「并排等权卡片」

AI 生成页最容易露馅的地方就是「N 张等宽卡片平铺」。本轮把三处结构性改掉：

| 区块 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 畲族文化 | 4 张等宽卡 | 编号大字（01–04）+ 三列横向条目，逐行分隔 | 编辑排版让「顺序」本身成为信息 |
| 凤凰落地（文创） | 12 张等权格 | 首件 2×2 特写大格（样品台处理）+ 其余网格 | 给视线一个落点，12 件不再同权 |
| 三大场景 | 3 张并排卡 | 竖向动线：节点 + 连接线 + 整行可点开演 | 它是一条动线，不是三个并列选项 |

配套：段落编号 01–07 用 Cinzel 描在标题左侧（原为描边空心，对比度不足已改实色）；
匠人两张访谈改成错落（第二张下移），不是两根等高柱子。

### 6.6.4 色彩：只用凤凰装三色，靠明度做层次

色板未新增颜色，仍是从凤凰装实物取的 红 `#B3202C` / 黑 `#0B0908` / 蓝 `#1E3A5F` + 金 `#D4A24C`。
本轮做的是**明度分层**：`--fg` 16.5:1 / `--fg-dim` 7.4:1 / `--fg-faint` 3.1→**4.0:1**（小字贴近 AA）。
文化卡片按序号轮换金/朱红/雾蓝三种强调色，用 `color-mix` 做光斑，不改底色。

### 6.6.5 动效：三种节奏，不是「全都淡入」

| 动效 | 用在哪 | 参数 |
|---|---|---|
| 标题墨迹扫出 | H1 | `clip-path` 从右向左揭开，1.25s `cubic-bezier(.16,1,.3,1)` |
| 幕布揭示 | 一木成像画布 | 覆盖层 `scaleY(1→0)` 1.15s |
| 错峰浮起 | 各网格子项 | `--d` 阶梯 × 80ms，最多 8 档 |
| 墨线生长 | 段落分隔 | `stroke-dashoffset` 2s |
| 导航下划线 | hover / 当前段 | `scaleX` 0→1，450ms |

全部在 `prefers-reduced-motion: reduce` 下归零（含幕布层直接 `display:none`）。

### 6.6.6 微交互：指针级反馈

- 按钮三级体系：主（金→朱红渐变 + 呼吸点）/ 描边 / 文字（hover 箭头右移）。
- AR 卡片与文化卡片：指针光斑跟随（`--mx/--my` 由 pointermove 写入，radial-gradient 定位），不是笼统的「上浮」。
- 文创特写图 hover 提亮去 sepia；纹章环 hover 缓慢自转；导航当前段有下划线常驻。
- 雕刻台滑杆滑块 hover 放大 1.12、按住 1.2（`grab`/`grabbing` 光标同步）。

### 6.6.7 响应式：修掉一个真缺口

**改前**：`@media (max-width:760px){.nav ul{display:none}}` —— 窄屏直接没有导航，
且没有汉堡菜单，手机用户只能一路滚。**这是功能性缺失，不是审美问题。**
**改后**：汉堡按钮（44×44）+ 整屏目录（逐条 -然后逐条 55ms 上浮）+ `aria-expanded` / `aria-hidden` /
Esc 关闭 / 点链接自动收起 / 视口放大自动复位。断点提到 860px（与 hero 断点对齐）。

多视口实测（agent-browser）：

| 视口 | 横向溢出 | 导航 | 最小可点 | H1 字体 |
|---|---|---|---|---|
| 360×780 | 0 | 汉堡 | 44px | ZCOOL 48px |
| 390×844 | 0 | 汉堡 | 44px | ZCOOL 48px |
| 768×1024 | 0 | 汉堡 | 44px | ZCOOL 58.4px |
| 1440×900 | 0 | 横向 | 44px | ZCOOL 104px |
| 1920×1080 | 0 | 横向 | 44px | ZCOOL 104px |

### 6.6.8 原创性：图形与字体都不借现成模板

- 凤凰图腾、粒子凤凰、雕刻台几何、AR 三段画面全部是**代码手绘参数化矢量**（零素材图、零 3D 模型）。
- 印章式「凤鸣」角标、墨线分隔、编号描字是自造的元素，无第三方 UI 框架痕迹。
- 字体是有性格的中文展示字体（站酷小薇）+ 罗马碑体（Cinzel），不是 Inter / Roboto 这类默认脸。

### 6.6.9 本轮踩到并修掉的真缺陷

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | `$(...).forEach`（应为 `$$`） | main.js 在进场动画处整段抛错，`window.__site` 未定义；页面「看起来正常」但所有 reveal 永不触发 | 4 处改回 `$$`，探针复验 `inCount` 从 0 → 正常 |
| 2 | 给被观察元素加 `clip-path` | IntersectionObserver 交叉矩形被裁空 ⇒ 永远判不可见 ⇒ 整块内容永久隐藏 | 改覆盖层幕布（不动被观察元素几何） |
| 3 | `.nav-toggle{display:none}` 重复声明 | 覆盖了媒体查询里的 `display:grid`，汉堡按钮永不出现 | 删重复声明，定位改绝对 |
| 4 | `.gitignore` 行内注释 | `_qa/   # ...` 被当成字面模式，忽略规则失效 | 注释独立成行 |
| 5 | `.sec-idx` 描边空心 | 对比度 1:1，编号等于不可见 | 改实色 72% 金 |
| 6 | 文创特写白底样片直接入暗色页 | 像贴了一块白纸 | 做「样品台」：径向遮罩 + 压暗 + 暖调统一 |

### 6.6.10 门禁升级（每条都做过反向验证）

`tools/verify_site.py` 新增 6 条，均为「会静默退化」的项：

| 判据 | 反向验证 |
|---|---|
| 字体自托管：woff2 数量/体积/入版本控制/@font-face 引用存在/font-display:swap/零 Google Fonts | 改坏引用 → FAIL |
| 字阶：11px 下限 + `--fs-*` 成体系 | 塞 0.625rem → FAIL |
| 移动端导航：汉堡 + 整屏目录 + aria + 断点 | 删 `id="nav-toggle"` → FAIL |
| 设计结构：编号/墨线/动线/特写格的 DOM 与 CSS 同时存在 | 改坏 `.merch-item.is-feature{` → FAIL |
| 首屏关键路径 ≤ 400KB（HTML+CSS+字体+首屏脚本） | 垫 420KB → 793KB → FAIL |
| 版本对账：CSS `--build` ⇄ HTML `BUILD` 同值 + 防循环闸 | 改成 9 / 删闸 → 各自 FAIL |

**总预算口径修订**：整站 1200KB → 1600KB。理由写清楚——零外链是硬约束，
字体 238KB 的成本不能甩给 CDN，所以记在本地账上；补偿是新增了更贴近体感的「首屏关键路径 ≤ 400KB」，
实测 **373KB**。整站实测 1125KB / 38 文件。

### 6.6.11 版本对账守卫（改版后老访客不崩版）

站点有 Service Worker，静态资源 cache-first。改版后老访客第一次进来会拿到
**新 index.html + 旧缓存 main.css** —— 新结构没有对应规则，会渲染成一堆无样式文本，
比白屏更像「网站坏了」。`VERSION` bump 救不了这一次。
解法：CSS 顶部写 `--build:3`，HTML 内联守卫读它并与自身 `BUILD` 对比，
不等则注销 SW + 清 caches + 重载一次（`sessionStorage` 防循环闸，不会无限刷新）。
实测：注入 `--build:2` → 守卫触发 → 加载后 `--build` 回到 3、`guardKey` 复位，`navigation.type=reload` 一次即止。
