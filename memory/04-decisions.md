# 关键决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 宿主 | GitHub Pages 主 + pages.dev 备 | github.io 微信内实测可开；pages.dev 有微信拦截实证风险 |
| 首版范围 | 凤凰单场景完整闭环 | 三天内三场景全做会摊薄质量 |
| 第二轮范围 | 补齐三场景：造像 72s / 红色 44s / 凤凰 36s | 命题原文就是「三大场景」，只差此步即闭环 |
| 风格 | 凤凰装配色（红/黑/蓝 + 金丝银线）+ 粒子流光 | 取色直接来自凤凰装实物描述 |
| 图腾 | 代码手绘原创 SVG | 矢量、无版权风险、可直接印文创 |
| 粒子动画 | Canvas 2D 粒子（非视频/非 Three.js） | 可交互、可降级、首屏轻 |
| **AR 技术路线** | **Canvas 2D 参数化矢量 + 摄像头取景底片；不引 three.js / AR.js** | 素材只有实拍照片与手绘草图，无可追踪三维资产；引入 3D 框架会 +500KB~2MB 且微信内置浏览器 WebGL 不稳。改走「屏幕空间叠加」：视频铺底 + 半透明动画层，现场观感仍成立 |
| **AR 版式** | 宽屏主体靠右留左侧解说；窄屏主体占上半屏 | 竖屏手机若画面铺满会吃掉文字区，实拍截图验证后改成安全区布局 |
| 识别 | 暖色像素占比判定（不引 CV 库） | 避免 +600KB wasm 拖慢首屏；且现场只需「对准即可开演」 |
| 集章/计时 | localStorage 本地持久化 | 零后端、零账号；现场换设备不串数据 |
| 文创 | 十二件，四档分层 | 覆盖现场发放到高客单礼盒 |
